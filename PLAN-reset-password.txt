RESET DE CONTRASEÑA (admin de empresa + superadmin, contraseña temporal)
==========================================================================
Implementado: 2026-08-21

CONTEXTO
--------
Hasta esta fecha no existía ningún mecanismo de "olvidé mi contraseña" en el
sistema -- ni self-service ni administrado. No había endpoint, no había link
en login.vue, y el único lugar donde se escribía un password_hash era al dar
de alta un usuario nuevo. La única forma real era tocar la base de datos a
mano.

Se implementó la mitad "administrada" del flujo completo: un admin de
empresa (para usuarios de su propia empresa) o un superadmin (para usuarios
con rol admin) resetean la contraseña de otro usuario, con una temporal que
el propio usuario debe reemplazar por una permanente en su próximo login.
El reset self-service por email queda para una fase futura, sin fecha.

Criterio de seguridad confirmado con el usuario: "admin/sistema define la
temporal, el usuario define la permanente al entrar" -- patrón estándar de
la industria. Se sumaron 4 refuerzos de seguridad no pedidos explícitamente
pero baratos y consistentes con convenciones ya existentes del proyecto:
  1. La temporal vence a las 24h si nadie la usa (pedido explícito del
     usuario, el plan original tenía 48h).
  2. El reset revoca todos los refresh_tokens activos del usuario.
  3. La temporal se muestra una sola vez, nunca se guarda en texto plano
     ni se audita.
  4. La permanente exige min_length=8 y no puede ser igual a la temporal.

DISEÑO -- BACKEND
-----------------
- Migración `0035_password_temporal.py`: 2 columnas nuevas en `usuarios`
  (`debe_cambiar_password` bool, `password_temporal_expira` timestamptz).
- `security.generar_password_temporal()`: alfabeto sin 0/O/1/l/I (se puede
  dictar por chat/teléfono sin ambigüedad).
- `refresh_tokens_repo.revocar_todos_de_usuario()`: nueva, revoca todo lo
  vigente de un usuario de una sola vez.
- `usuarios_service.resetear_password(db, usuario, actor_id, empresa_id)`:
  lógica compartida (genera temporal, hashea, marca debe_cambiar_password,
  fija vencimiento 24h, revoca tokens, audita SOLO si hay empresa_id).
  Reusada por:
    - `usuarios_service.resetear_password_superadmin` (sin empresa_id,
      mismo precedente que el toggle de puede_crear_empresas: no se audita
      en auditoria_cambios por no tener empresa asociada).
    - `usuarios_empresas_service.resetear_password` (con empresa_id, para
      el camino de admin de empresa -- bloquea auto-reset con 422).
- 3 endpoints:
    POST /empresas/actual/usuarios/{usuario_empresa_id}/resetear-password
      (require_roles("admin"))
    POST /mis-empresas/{empresa_id}/usuarios/{usuario_empresa_id}/resetear-password
      (require_admin_de_empresa -- agregado por simetría con el resto de
      ese router, aunque accesos.vue todavía no lo dispara desde ningún
      botón)
    POST /usuarios/{usuario_id}/resetear-password
      (require_superadmin -- solo alcanza a los usuarios que ya lista
      GET /usuarios: admins con rol activo en >=1 empresa)
  Los 3 devuelven PasswordResetOut { password_temporal, expira_en }.
- `auth_service.autenticar()`: rechaza el login con 401 si la temporal ya
  venció, aunque la contraseña sea correcta.
- `auth_service.cambiar_password_temporal()` + POST /auth/cambiar-password-temporal:
  valida la temporal contra el hash, exige min_length=8 y que la nueva sea
  distinta de la temporal, revoca tokens y emite un par nuevo (sin empresa,
  igual que un login fresco).
- `deps.py::get_usuario_actual`: EL GATE REAL. Mientras
  usuario.debe_cambiar_password sea true, cualquier endpoint que no esté en
  {/auth/me, /auth/logout, /auth/cambiar-password-temporal} responde 403 --
  no depende de que el frontend coopere.

DISEÑO -- FRONTEND
------------------
- useAuth.ts: Usuario.debe_cambiar_password, cambiarPasswordTemporal().
- login.vue: chequea el flag (via hidratarSesion()) ANTES de listarEmpresas()
  -- si no, esa llamada caería en el 403 del backend y el catch genérico
  mostraría "Email o contraseña incorrectos" por error.
- middleware/auth.global.ts: fuerza /cambiar-password-temporal antes incluso
  de /seleccionar-empresa.
- Página nueva /cambiar-password-temporal (formulario: temporal, nueva,
  confirmar).
- Componente nuevo PasswordTemporalModal.vue (modelado sobre
  ConstanciaPagoModal.vue, el único UModal del proyecto): muestra la
  temporal una sola vez con advertencia, sin acción a confirmar (el reset
  ya ocurrió en el backend).
- Botón "Resetear password" agregado en empresa/usuarios.vue (por fila) y
  en el panel "Permisos de administradores" de seleccionar-empresa.vue
  (solo superadmin).
- Gotcha recurrente del proyecto (ya documentado en memoria para
  composables nuevos): un COMPONENTE nuevo bajo frontend/app/components/
  tampoco lo recoge el server de dev de Nuxt ya corriendo -- mismo fix,
  `docker compose restart frontend`.

VALIDACIÓN
----------
- Backend: 11 tests nuevos en tests/test_reset_password.py, todos en verde
  (login con temporal, bloqueo 403 fuera del allowlist, cambio de
  password, auditoría, revocación de tokens, expiración, validaciones de
  longitud/igualdad, ambos caminos de admin de empresa, camino de
  superadmin, rechazo de admin normal a la ruta de superadmin). Suite
  completa: 201/201 (190 previos + 11 nuevos), corrida contra Postgres
  real vía Docker.
- Migración corrida con éxito contra la BD de dev
  (`docker compose exec backend alembic upgrade head`).
- Frontend: `npm run lint` y `npm run typecheck` en verde (0 errores, 0
  warnings tras resolver una colisión de nombre entre 2 interfaces
  PasswordResetOut auto-importadas).
- Prueba manual end-to-end en navegador real (Docker, BD de dev):
    1. Admin resetea password de "Usuario Contador 2" en empresa/usuarios.vue
       -> modal muestra la temporal generada.
    2. Login con la temporal -> redirect forzado a /cambiar-password-temporal.
    3. Define la permanente -> cae en /seleccionar-empresa -> app usable con
       normalidad (rol contador, 2 empresas visibles).
    4. Mismo flujo repetido desde el panel de superadmin en
       seleccionar-empresa.vue (reset de "maurico") -> modal funciona igual.
  Los 2 usuarios de prueba tocados durante la verificación manual
  (contador2.test@nomina.internal, maurico@panama.com) se restauraron
  después a password "dev12345" con debe_cambiar_password=false, para no
  dejar credenciales de prueba en un estado confuso para el equipo.
